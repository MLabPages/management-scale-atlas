## ローカルで最初に行うこと

1. 実行環境とプロキシ設定の有無を確認し、公開URLへの接続試験をする。認証情報の値を出力しない。ローカルなら必ず接続できるとは仮定しない。
2. スクリプトはNodeを使用する。環境プロキシがある場合はNode 24.5以降が必要。依存追加は原則不要。
3. ローカルクローンまたは作業ツリーのルートで次を実行する。

```sh
node verify-data.mjs
node collect-literature.mjs --output collection/queue.json
node collect-literature.mjs --search --limit 1 --id target:absorptive-capacity --output collection/candidates.json
```

1件の検索で接続・応答・候補保存が成功したら、優先候補を選んで収集を広げる。既存出力があればDOIで候補を統合し検索ログを追記する。キューの先頭を同じ`--limit`で繰り返し検索するだけでは全件更新にならないため、`--id`で対象を選ぶ。`--since`は索引更新日であり出版日ではない。

## 次の収集・検証

1. 主要尺度の領域別チェックリストを具体化する。特に戦略・組織能力の追加候補A、主要な別測定系統と既存HOLD候補を優先する。主要尺度をすべて網羅したとは未認定。
2. 原典・出版社・著者公式資料、Crossref/OpenAlex、CiNii Research、J-STAGEを使い分ける。書誌検索だけではなく本文の方法・表・付録から実使用・項目数・版を確認する。現在の自動収集接続先はCrossrefのみ。
3. 使用研究0〜1件の尺度、日本語根拠未確認の尺度、尺度間関係のレビュー・メタ分析を増補する。レビュー対象期間・領域・尺度版を記録する。
4. 関係の根拠の厚みを、独立研究グループ、標本重複、分析水準、対象集団・文化、原版／調整版、横断／縦断／実験、効果量・信頼区間、結果の一貫性で整理する。単純な被引用数・論文数・αだけで品質を認定しない。
5. 「近いが根拠未確認」の候補は、検索語・データベース・検索日・期間・言語・採否基準を記録して調べる。未調査と範囲内で確認できなかった状態を分け、「未検証」と断定しない。
6. 確認できた尺度・使用研究・関係を正本データへ登録し、出典・検証結果・限界を表示する。原版、正式短縮版、翻訳版、研究内削除版を混同しない。項目本文や利用条件を推測して追加しない。

公開APIは主に書誌情報を提供する。API接続が成功しても、有料論文の本文アクセスや尺度項目の利用許可が得られたことにはならない。
